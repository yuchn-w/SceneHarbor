# 資源策略與實測範圍

## 如何降低負載

在「設定 → 效能」選擇極省資源：Scene 桌布使用 15 FPS、50% 渲染比例，停止預載下一張。省電模式為 24 FPS、75%，也不預載。減少螢幕數量、選擇較簡單的場景或改用影片，也會影響負載。

降低影格率與渲染比例主要減少每秒渲染工作；場景原始材質仍需載入，因此不能保證 RAM 依同比例下降。第三方場景、網頁內容及實驗性鎖定畫面的資源需求可能不同。

鎖定、螢幕保護或切換使用者時，桌面 renderer 暫停，解鎖後沿用原程序恢復；鎖定畫面的獨立 renderer 可繼續播放。這種暫停減少 CPU／GPU 工作，但會保留恢復所需的材質記憶體。手動停止或嚴重記憶體壓力停止才會釋放 renderer。

系統記憶體警告會清理預載，嚴重壓力時停止桌布與預覽，並要求手動恢復，避免反覆啟動。預覽記憶體快取同時受數量與位元組限額約束。

## 2026-10-10 同機觀察

以下比較本次開發版本 build 58 與 build 59，**不是所有機型或桌布的效能保證**。條件為同一台 Apple Silicon Mac、macOS 27.0.1、兩個 Scene 桌布、保留相同使用者設定、鎖定狀態，各觀察約 5 分鐘。沒有用測試程式注入整台 Mac 的記憶體壓力。

CPU 由程序累積 CPU 時間的差值計算，100% 代表一個核心；RAM 使用 `vmmap` 的 physical footprint，並非 RSS。

| 程序／觀察 | build 58 | build 59 |
| --- | --- | --- |
| 主程式 CPU 中位數 | 約 27% | 約 0.2% |
| 兩個桌面 renderer 合計 CPU 中位數 | 約 10% | 約 2.2% |
| 主程式 physical footprint | 約 133 MiB，觀察期間穩定 | 約 110 MiB，觀察期間穩定 |

CPU 改善符合本次修正：停止重複發布相同效能狀態，並在鎖定時暫停桌面渲染。記憶體差異可能也受初始化與快取狀態影響，不將這個差值宣稱為固定節省比例。

另有既存長駐的鎖定延伸功能，約 1.4 GiB；它不是這次新啟動的主程式，沒有將其混算成主程式數值。各程序可能共用圖形記憶體，不直接把所有 footprint 相加當成唯一實體用量。

以 IOKit 觀察整機 GPU，修正前的短樣本約 91–97%，修正後暖機後樣本約 43–74%。這包含系統、鎖定畫面與其他程式，取樣時段長度也不同，不能單獨歸因 SceneHarbor，亦不計算 App 的 GPU 改善百分比。

另一次單一隱藏 Scene 的極省資源測試（15 FPS／50%）完成首幀與畫面擷取，footprint 約 463 MiB、峰值約 608 MiB。它不代表整個 App 或一般作品的最低需求。

另有約 15 分鐘、46 個取樣點的混合操作觀察，包含後段解鎖、作品切換與設定操作。安裝版主程式 footprint 約 111–154 MiB；同一個桌面 renderer 約 359–440 MiB，另一個因作品切換而替換程序。後段 UI 驗收曾另開同版建置副本，未計入此組程序取樣，已於收尾關閉並移除。因此這段不作為整體 App 負載、程序數或長期記憶體成長的結論；上方五分鐘鎖定比較是在這個副本啟動前完成。

## 還不能宣稱什麼

這些短時間觀察沒有證明數天連續執行、所有作品、所有顯示器或全部操作循環都不會出問題。核心回歸、快取／壓力政策與原生影格生命週期檢查，不能取代實際長時間使用回饋。完整驗證範圍見 [RELEASE_CHECKS.md](../RELEASE_CHECKS.md)。
